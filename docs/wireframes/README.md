# Voidbound UI 线框图与设计方向

> 当前存档版本对应的全部屏布局梳理。每屏包含:
> - 绘制函数定位 (`src/main.ts` / `src/render/hud.ts:行号`)
> - ASCII 线框图(尽可能按实际像素尺寸标注)
> - 关键交互(键盘 + 鼠标等价按钮矩形)
> - 状态变体(有/无存档、死亡/硬核、设置开/关)

---

## 设计方向判断 (Design Direction)

| 维度 | 判断 |
|------|------|
| **目的 (Purpose)** | 2D 俯视肉鸽 ARPG,HUD 是战斗生命线,菜单屏是单次深度交互(选职业/读装备) |
| **受众 (Audience)** | 30-60 分钟一局的硬核动作玩家,需要高密度、可扫读、状态清晰的信息布局 |
| **语调 (Tone)** | **Dark utilitarian dense**(暗黑 + 实用 + 紧凑)。非营销、非极简、非华丽 |
| **记忆点 (Memorable Detail)** | 金/紫双品牌色 `#ffd64a` × `#c9aaff`,严格状态色编码 + Boss 入场全屏紫光脉动 + 符文三选一紫边 |
| **约束 (Constraints)** | Canvas2D overlay (`hudCtx`) + WebGL2 层 + 鼠标/键盘双路径 + Tauri 可变窗口尺寸 + 渲染每帧,需避免重阴影/渐变 |

## HUD 6 区分屏(战斗屏核心)

源自 `hud.ts` 注释 §9.1:

```
┌─────────────────────────────────────────────┐
│ [左上] HP/MP/EXP/Lv      [右上] 金/积分/击杀/难度 │
│ [中上] Boss 血条 + COMBO + Toast               │
│ [中下] 世界画布 (玩家/怪物/VFX)               │
│ [左下] 技能 Q/F/E/R + 药水 + 翻滚 + 技能点   │
│ [右下] 日志 (WRN/ERR only)                  │
└─────────────────────────────────────────────┘
```

## 已做对的事

1. **状态色编码稳定**:红=血/危险,蓝=信息/选中,金=资源/主操作,紫=符文/特殊
2. **鼠标 + 键盘双路径完整**: 所有键盘 1/2/3/Enter/Esc 都有等价按钮矩形
3. **关键交互区在视场中心**: 技能簇/药水/Boss 血条都在视线焦点,玩家不需要大幅移动视线
4. **品牌记忆点**: B-V2 Boss 入场横幅 + 全屏泛光脉动 (3 个召唤点接线)

---

## 改进机会 (按优先级)

1. **菜单屏缺乏视觉锚定**: 标题/新游戏/角色管理都是纯文字 + 边框,暗黑但缺记忆点。建议加低饱和度 hero 图作为视觉锚(类似暗黑 2 选角色背景插画)
2. **HUD 拥挤**: 战斗屏同时铺 12 个区块,持续 30-60 分钟会疲劳。技能点提示挤在左下,建议挪到等级附近
3. **城镇面板**: `drawTownPanel` 7 类 NPC 功能差异大,锻造/传送师服务项可能溢出。建议分两栏:左 NPC 列表 + 右服务面板
4. **设置面板**: 440px 高度塞音量/全屏/难度 + 5 个键位 + 高级提示,密度过高。考虑分组加小标题分隔
5. **角色管理列表**: `state.charList.slice(0, 8)` 只显示前 8 个,超 8 角色时下拉/滚动机制缺失
6. **品牌色**: 金/紫确实是好记忆点,但全 monospace + 12-15px 字号削弱了冲击力。建议标题页 / Boss 入场换更大字号 + 更饱和处理
7. **字体层次**: 保留 monospace 作为基体,标题用更紧字距或加宽以加强层级
