## 1. 背景与目标

标题屏现状(`drawTitle`,src/main.ts:1970):`#0b0b12` 纯黑全屏 + 72px 紫色标题 + 18px 副标 + 3 个纯文字菜单项;有存档时右侧展示最近 5 角色卡片(main.ts:1987-1994,按 `last_played` 降序)。

**核心问题:玩家打开游戏 5 秒内看不出这是 2D 俯视 ARPG,标题屏无视觉锚、无氛围、无玩法信息。** 本文档将审查列出的 10 条改进机会转为任务,含反模式护栏(§5),按"改动小收益大"优先。

已核实的前提(2026-08-12 代码核查):
- `CLASS_SPRITES` 立绘映射存在(src/game/class.ts:58),角色管理屏已用 `characters` 图集绘制站桩(main.ts:1903)
- `npcs/portal_array` 传送阵贴图(main.ts:1536)、`ui/slide_horizontal_color` 光环贴图(main.ts:1533/1539)均在用
- `state.envFx` 环境粒子结构已存在(state.ts:272,OPT-027 产物)
- `state.charList[].last_played`(unix 秒,main.ts:1924)、存档 `scene` 字段(src/ipc/save.ts:76)、`state.run.alive/total`(state.ts:163-207)均在,TS-003 数据源零新增
- `keyHintMain()` 已走 `loadKeybinds()`(main.ts:1793-1795)→ TS-010 大概率已闭环,只差验证

## 3. 任务条目

> 编号 TS-xxx;`优先级` 沿用审查分级;验收标准为可执行判断(项目无 E2E 基建,UI 类手动确认视觉,沿用 OPT 计划 §6 约定)。

### 🔴 高优先级

#### TS-001 首页视觉锚 — 传达"这是 2D 俯视 ARPG"
- **优先级**:🔴 高 | **估时**:1h(方案 A)
- **需求**:标题屏右下角渲染 200×200 站桩角色立绘 + 脚下光环。三种方案任选,推荐 **A**:
  - A. 静态立绘(推荐):复用 `CLASS_SPRITES` + `characters` 图集,右下角 200×200;脚下加 `npcs/portal_array` 或 `ui/slide_horizontal_color` 浅光(参照 main.ts:1533/1539 的 NPC 脚下光环画法)。立绘随 `state.currentChar` 职业变化
  - B. 缩略游戏窗口(成本中):320×240 小窗实时渲染 30s 循环 demo(移动 + 火球 + 击中),复用现有 drawFrame 管线 — 风险高,不推荐本期做
  - C. 像素场景截图(成本低):dungeon 场景静态图半透明叠加背景 — 需新增导出/素材流程
- **验收标准**:
  - [ ] 标题屏右下角可见角色立绘 + 脚下光环,不遮挡主菜单/卡片区
  - [ ] 有存档时立绘与"继续游戏"卡片职业一致(读 `currentChar` 对应 `charList` 的 class)
  - [ ] 无存档时显示默认职业(barbarian)立绘
  - [ ] 60FPS 稳定(单 sprite 静态绘制,无每帧图集重载)
- **涉及文件**:src/main.ts(drawTitle)、src/game/class.ts(CLASS_SPRITES 已存在)
- **依赖**:—
- **反模式护栏**:只加 1 个静态元素,不加装饰 blob、不加营销卡片

#### TS-002 背景"死黑" — 加氛围渐变 + 微尘
- **优先级**:🔴 高 | **估时**:1h
- **需求**:替换整屏纯 `#0b0b12`(main.ts:1972-1973):
  1. 径向渐变:中心略亮(微紫 `rgba(40,20,60,0.4)`),边缘回 `#0b0b12`。Canvas2D 参考:
     ```js
     const g = hudCtx.createRadialGradient(w/2, h/2, 100, w/2, h/2, Math.max(w,h)*0.7);
     g.addColorStop(0, 'rgba(80,40,120,0.18)');
     g.addColorStop(1, 'rgba(0,0,0,0)');
     hudCtx.fillStyle = g;
     hudCtx.fillRect(0, 0, w, h);
     ```
  2. 慢速飘动环境粒子(灰色微尘 ~30 颗):复用 `state.envFx` 数据结构(state.ts:272)与现有粒子渲染路径,呈现"虚空"感
- **验收标准**:
  - [ ] 标题屏中心有可感知的微紫亮区,边缘仍为 #0b0b12
  - [ ] 微尘缓慢漂移,不闪烁、不影响菜单点击(hit-test 不包含粒子)
  - [ ] 60FPS 稳定(≤30 粒子;不引 shader 背景 — 反模式护栏)
- **涉及文件**:src/main.ts(drawTitle 背景块)、src/game/state.ts(envFx 复用)
- **依赖**:—

#### TS-003 继续按钮信息密度(重玩率)
- **优先级**:🔴 高 | **估时**:1h
- **需求**:现有"继续游戏"卡片/最近存档卡片(main.ts:1987-1994)仅一行摘要(职业 ID · Lv · 主题 · 难度),增加 3 个微信息:
  - 上次游玩距今:相对时间("3 小时前"/"昨天")— 数据源 `charList[].last_played`(main.ts:1924,unix 秒)+ `performance.now()` 换算
  - 当前所在场景图标:16×16,地牢/城镇 — 数据源存档 `scene` 字段(src/ipc/save.ts:76)
  - 跑局进度条:迷你横条,剩余怪/总怪 — 数据源 `state.run.alive` / `state.run.total`(state.ts:163-207);town 场景无跑局数据时隐藏或显示"—"
- **验收标准**:
  - [ ] 卡片显示相对时间且换算正确(0-59min"刚刚"/N 分钟前;跨天"昨天"/N 天前)
  - [ ] 场景图标与存档 scene 一致(dungeon/town 可区分)
  - [ ] 进度条数值 = alive/total,清图后满条;Boss 阶段显示 Boss 图标或进度满态
  - [ ] 无存档态(首启)不出现任何占位/NaN
- **涉及文件**:src/main.ts(drawTitle 卡片区)、src/ipc/save.ts(scene 字段只读)
- **依赖**:—
- **反模式护栏**:不新增卡片(继续按钮已是单卡,不堆副卡);时间/进度渲染用现有数据,不加新存储字段

#### TS-005 标题字效 + 副标玩家向文案
- **优先级**:🟡 中 | **估时**:0.5h
- **需求**:
  - 标题加细微外发光:`ctx.shadowColor = 'rgba(201,170,255,0.5)'; ctx.shadowBlur = 24`(标题屏为静态场景,每帧重绘开销可接受)
  - 副标题 18px → 22px,加字间距 `letter-spacing: 0.2em`(hudCtx 用 `ctx.letterSpacing` 或逐字绘制)
  - 副标文案玩家向化:去掉"(战斗原型)"开发者向括号,改为玩法描述,如 "WASD + 鼠标 · 30 分钟一局"
  - 可选(时间富余):标题上方加小 logo 元素(8×8 紫色方块 + 字模)
- **验收标准**:
  - [ ] 发光仅作用于标题文字,不产生全屏模糊/拖影
  - [ ] 副标新文案不含"(战斗原型)";字号/间距生效
  - [ ] 与其他屏(暂停/新局屏)文字渲染互不影响(注意 shadow 状态复位)
- **涉及文件**:src/main.ts(drawTitle)
- **依赖**:—
- **反模式护栏**:不发散成紫色渐变 blob;文案改动不扩到 README/其他屏(仅标题副标)
